# Apple TV 抖音原生播放器重构设计

## 目标

重写 TouchFishTV 的抖音播放模块，以 `AVPlayerViewController` 为唯一播放界面基础，提供稳定的上下切换、原生进度控制、原生标题信息和顶部弹幕。整体视觉遵循 Apple TV 的简约、克制和精致风格，不保留评论、作者页、喜欢按钮或自绘播放控制条。

## 范围

本阶段包含：

- 推荐视频流、关注视频流与只读“我的喜欢”视频流；
- 单一播放器连续播放；
- 播放状态下，上键切换上一条、下键切换下一条；
- 左右键使用系统播放器的快退、快进和进度控制；
- 标题与作者显示在系统播放器原生标题区域；
- 顶部 25% 高度范围内的滚动弹幕；
- 视频播完自动切换下一条；
- 加载、空状态与网络错误反馈。

本阶段明确不包含：

- 评论列表及评论入口；
- 作者详情及作者作品页；
- 喜欢或取消喜欢操作；“我的喜欢”仅展示已有列表，不提供操作按钮；
- 自定义进度条、自定义播放暂停按钮、自定义工具栏；
- 视频去重。

### 我的喜欢媒体库

“我的喜欢”先展示四列竖向卡片网格，点选卡片后才进入原生播放器。所有封面统一使用 3:4 占位并居中裁切，不使用模糊补边；卡片下方只显示单行标题，页面不重复显示“我的喜欢”标题或视频数量。卡片使用原生 Card 焦点动效。退出播放器后恢复到原卡片；播放器内可按上下键连续切换喜欢列表。

## 已验证的接口约束

- Cookie 可正常访问抖音数据。
- `xbogus` npm 模块仍然有效。npm 入口接收完整 URL，但会先截取 query 再调用算法本体；tvOS Bundle 内直接包含算法本体，因此必须传 query。
- 推荐流按上述签名契约生成 `X-Bogus` 后可返回 10 条视频。
- 关注流按上述签名契约生成 `X-Bogus` 后可返回 11 条视频。
- 喜欢列表不签名也可用，但本阶段不展示喜欢模块。
- 播放地址支持 HTTP Range，请求返回 `206 video/mp4`。
- 弹幕接口不签名可用，返回 `status_code = 0`；弹幕按 32 秒时间窗请求。
- Cookie 与动态签名数据只在运行时使用，不写入 Git 仓库。

## 架构

### DouyinFeedStore

负责推荐流和关注流数据、游标、预加载、刷新及错误状态。推荐接口按服务端实际批量使用 6 条请求，实际返回数量仍以响应为准；剩余 2 条时预取下一批。列表不去重，保持服务端原始顺序；连续播放时只裁剪已经播放过的历史，当前项向上最多保留 5 条，当前项及后续待播列表不受该限制。Store 不直接控制播放器，只发布当前视频、播放序列和相邻视频状态。

### PlaybackCoordinator

持有全模块唯一的 `AVPlayer`。每次切换执行固定顺序：增加播放 generation、取消旧任务、暂停播放器、取消旧 item 的 seek/preroll 与 asset 加载、移除旧 `AVPlayerItem`、清空旧弹幕、创建新资源、设置原生元数据、替换 item、开始播放。每条视频将前向缓冲限制为 8 秒，关闭面向长视频的自动最小化卡顿等待，并在已有数据时立即播放。

任何资源加载、弹幕请求或播放结束通知都必须校验当前 generation 与播放序列，防止上一条视频的异步回调影响新视频；播放序列独立于视频 ID，因此相邻重复视频仍会重新安装 item。

### DouyinPlayerContainerViewController

使用普通容器控制器承载 `AVPlayerViewController`，不重写系统进度条。容器负责遥控器事件仲裁、播放器生命周期和弹幕覆盖层。

### DanmakuOverlayController

附加到 `AVPlayerViewController.contentOverlayView`，但不拦截焦点与遥控器操作。它负责分窗请求、轨道调度、播放时间同步、暂停恢复、seek 重建和切换清理。

## 遥控器交互

- 视频正在播放且系统播放控件未激活时：上键切换上一条，下键切换下一条。
- 视频暂停、系统控件可见或焦点位于系统按钮时：上键和下键完全交给系统焦点引擎，不切换视频。
- 左键和右键始终交给 `AVPlayerViewController`，用于原生进度控制。
- 点按播放暂停键由系统播放器处理。
- 点按中心键唤起或操作系统播放控件。
- Menu/Back 键使用系统返回行为，本阶段不打开评论或作者页面。
- 第一条视频按上键不循环；最后一条按下键先加载下一批，成功后切换，失败时保持当前视频。

快速连续按上下键时，只接受一次在途切换。新视频 item 安装完成后才允许下一次切换，避免索引越界和多个视频同时播放。

## 原生信息展示

视频标题和作者通过 `AVPlayerItem.externalMetadata` 提供：

- Title：视频描述；为空时显示“无标题”；
- Subtitle：作者昵称；为空时显示“未知作者”。

`transportBarIncludesTitleView` 保持开启，使信息显示在系统进度条标题区域。视频画面上不额外绘制标题卡片。

## 弹幕视觉与行为

- 弹幕活动区域固定为播放器画面顶部 25%，不进入下方 75%。
- 使用白色、约 88% 不透明度的系统无衬线字体，配细黑色描边和轻微阴影；不使用胶囊背景。
- 字号依据 1080p 画面保持电视观看距离可读，并随有效画面尺寸有限缩放。
- 轨道保持统一行高和安全间距；同轨前后弹幕不会追尾或重叠。
- 超长文本做单行宽度上限和尾部省略，不缩小到不可读。
- 根据区域高度限制轨道数和同屏数量；高密度时排队或丢弃过期弹幕，不覆盖整个画面。
- 弹幕匀速从右向左移动，使用线性动画，不使用弹跳、缩放或高饱和颜色。
- 播放暂停时弹幕同步暂停；恢复播放时继续。
- seek 后清空屏幕并按新时间重新建立待显示队列。
- 每次请求 32 秒窗口，在当前窗口中段预取下一窗口；同一窗口只请求一次。
- 切换视频时立即取消旧请求、移除所有旧弹幕并重置时间窗口。

## 视觉语言

- 画面以视频内容和系统播放器为主，不增加长期驻留的导航栏或侧边栏。
- 加载状态使用居中的系统 `ProgressView` 与一句短文案。
- 空状态和错误状态使用 SF Symbols、系统字体、原生焦点按钮及宽松留白。
- 视频切换采用约 0.18 秒的轻微淡入，避免黑屏闪烁，不使用滑页、弹簧或大幅缩放。
- 自定义层均不得伪装成系统进度条或系统按钮。

## 错误处理

- Feed 返回空响应时显示可重试错误，不把 HTTP 200 当作成功。
- 视频 URL 无效或 item 播放失败时停止当前 item，显示简短错误，并允许用户切换到相邻视频。
- 弹幕请求失败不影响视频播放；当前窗口静默无弹幕，后续窗口仍允许重试。
- Cookie 失效时显示设置入口，但不在日志中输出 Cookie、令牌或完整签名 URL。
- 加载更多失败时保持当前列表与当前播放位置，不自动跳回或清空页面。

## 可测试边界

自动测试覆盖：

- npm 包装层与 tvOS 内置算法本体的签名输入契约；
- 播放切换状态机和 generation 失效机制；
- 暂停或原生控件激活时禁止上下切换；
- 快速连续切换只安装最后有效 item；
- 元数据标题与作者映射；
- 32 秒弹幕窗口计算与预取；
- seek、切换和销毁时清空弹幕；
- 顶部 25% 区域计算与轨道数量限制；
- Feed 加载失败时保留当前列表。

在 Mac 的 tvOS 模拟器上人工验证：

- 上下切换时旧视频声音立即停止；
- 暂停并激活系统控件后，上下键只移动系统焦点；
- 左右键始终操作系统进度条；
- 原生进度条区域正确显示作者与标题；
- 弹幕只出现在顶部 25%，暂停、seek 和切换均保持同步；
- 1080p 下文字清晰、间距自然，无自绘控件粗糙感。

本地 Windows 负责代码、静态检查和提交；Mac 端由用户拉取后运行 tvOS 模拟器测试，不使用远程 SSH。
